# 자동 테스트 보고서 — 2026-11-04

대상: main `3b2c45a`, 앱 v35. 검토 브랜치 `codex/e2e-tests`. 앱·서비스워커 코드는 수정하지 않았다.

## 실행법 (3줄)

```sh
npm install
npx playwright install chromium webkit
npm test
```

## 환경과 범위

- Windows, Node 22.23.1, Python 3.11.9, Playwright 1.64.1. Chromium 156.0.8078.4, WebKit 27.2 (Playwright의 Windows 빌드).
- 모든 컨텍스트에서 `serviceWorkers: 'block'`, 새 저장 공간, 카메라 거절을 사용한다. 한국어·영어 각각 검사한다.
- 외부 CDN 폰트 요청은 빈 CSS로 대체한다. 로컬 시스템 폰트로 검사하며, CDN 가용성과 실제 웹폰트 레이아웃은 범위 밖이다.
- 이미지 입력은 테스트 안에서 canvas로 만든 800×1000 PNG뿐이다. 왼쪽 RGB(240,225,170), 오른쪽 RGB(220,170,130). 사람 사진이나 실제 카메라 영상은 사용하지 않는다.
- 공유 API는 가로채 문구만 검사한다. 실제 외부 공유는 발생하지 않는다.
- `page.screenshot()`의 PNG를 다시 canvas로 읽어 화면의 5×5 픽셀 평균을 검사한다. 원본 이미지의 픽셀이나 CSS 속성만으로 필터 성공을 판단하지 않는다. 검은 화면 오탐도 막는다.

통과한 픽셀 검사 3건의 실제 평균은 보정 전 `[240,225,170~171]`, 보정 후 `[214,214,214]` 또는 `[215,215,215]`였다. 보정 후 채널 차이는 모두 0으로 기준 12 이하다.

## 실행 환경 이슈와 해석

- **확실:** npm 설치가 초기화 단계에서 멈춰 공식 npm 레지스트리에서 동일 버전의 `@playwright/test`, `playwright`, `playwright-core`를 받아 로컬에서 실행했다. 선언한 개발 의존성은 `@playwright/test` 하나뿐이며 정확한 버전을 고정했다. 브라우저는 공식 Playwright 설치기로 설치했다.
- **확실:** 설치 진행 중의 예비 Chromium 실행은 16통과·1실패였다. 실패는 테스트 본문 시작 전 `worker process exited unexpectedly (code=3221226505)`였다. **모름:** 워커 종료의 근본 원인. 설치 완료 후 단일 워커 전체 실행에서 Chromium 17건은 통과했다.
- **확실:** WebKit 사진 테스트 결과가 통과해도 실제 iPhone Safari의 카메라 영상 필터를 검증한 것은 아니다. **확인 필요:** 실기기 영상의 `filter:url(#wbf)`와 노치·주소 표시줄 변화. 영상 필터 대안은 프로젝트 타워가 판단한다.
- 문서 전체의 가로 스크롤 검사만으로, `overflow:hidden` 안에서 버튼이 잘리는 문제까지 검증되지는 않는다. ③에서 팝업·목록 내부 경계와 버튼 크기를 별도로 검사한다.

## 산출물과 제안

- `app.spec.js`: 사용자 경로와 검증. `helpers.js`: 카메라 차단, canvas 합성 입력, 공유 가로채기, 화면 픽셀 읽기.
- `test-results/results.json`: 마지막 실행 상세 결과(재생성 가능, Git 제외). 실패 시 스크린샷·trace 보존. 보정 픽셀과 PNG는 테스트 첨부에 남는다.
- 프로젝트 타워는 이 브랜치의 테스트와 ③ CSS 수정을 함께 검토한 뒤 main 반영 여부를 결정한다. 이 작업에서는 main 병합·푸시·배포를 하지 않는다.
