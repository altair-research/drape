```text
  예: 왼쪽 절반 rgb(240,225,170)(노란 조명 속 흰 종이), 오른쪽 절반 rgb(220,170,130). #file 입력에 setInputFiles 로 넣는다.

  4) 결과 공유: navigator.share 를 가로채 #shareResult 클릭 → 문구에 계절 개수 줄과 "쪽"(영어 "Leaning") 줄이 있는지.
```

## ② 색 데이터 감사

```text
저장소: altair-research/drape (로컬 C:\dev\drape). 공개 저장소다 — 이메일·키·비밀번호를 파일에 쓰지 마라.
앱: index.html 한 파일짜리 퍼스널컬러 거울. 스크립트 안에 SEASONS(4계절 색 목록, 이름 ko/en), LEVELS(흐리게/기본/선명하게 3단계), variantHex(), seasonSwatch(), leanCuts()/leanOf()(내가 고른 색 요약의 채도·밝기 경계 = 팔레트 하위·상위 1/3, 온도 = colorWarmth ±0.25) 가 있다.

할 일: tools/audit-colors.mjs (Node, 외부 패키지 없이) 를 만든다. index.html 을 읽어 마지막 <script> 에서 필요한 상수·함수를 정규식/vm 으로 꺼내 쓴다. index.html 은 고치지 마라.
검사:
 1) 모든 색 × 3단계 variantHex 결과가 #RRGGBB 형식인지, 같은 계절 안에서 서로 너무 비슷한 색(CIEDE2000 ΔE < 3) 쌍.
 2) 이름 빠짐: 각 색의 ko·en 이름이 비었거나 중복인 것.
 3) 글자 대비: 화면에서 색 위/옆에 쓰는 글자(흰 글자 #FFFFFF 와 앱 배경 근처 어두운 색) 대비 WCAG 비율 — 4.5 미만인 색 목록(정보용, 실패로 막지 않음).
 4) 계절 막대 대표색(seasonSwatch) 4개끼리 ΔE — 봄·가을이 둘 다 노랑이라 구분이 약하다는 걸 이미 안다. 수치로 보이고, 더 잘 갈리는 대안 색(각 계절 팔레트 안에서 고름) 제안.
 5) 요약 경계값: 무채색 뺀 전체에서 부드러운/중간/선명한, 밝은/중간/깊은, 웜/쿨/무 개수 분포. 계절마다 "기대 방향"(봄 웜·밝음·선명, 여름 쿨·밝음·부드러움, 가을 웜·깊음·부드러움, 겨울 쿨·깊음·선명)과 얼마나 맞는지 % — 한 계절의 색만 다 ♥했을 때 요약 한 줄이 무엇이 나오는지 4줄로.
출력: `node tools/audit-colors.mjs` 가 표를 콘솔에 찍고 docs/COLOR-AUDIT.md 를 만든다(검사별 결과, 문제 목록, 제안. 확신도 표기). 제안은 제안으로만 — 앱 코드는 바꾸지 않는다.

커밋 메시지에 AI 공동저자 줄을 넣지 마라. main 에 병합·푸시하지 마라. 브랜치는 푸시해도 된다.
```
